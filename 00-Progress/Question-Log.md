| # | 選項 | 描述 |

### Q2 — 05-Sliding-Window / 0239 Sliding Window Maximum — Key insight

> 0239 Sliding Window Maximum 的單調遞減 deque，新元素 nums[i] 入隊前會把隊尾所有 ≤ nums[i] 的元素彈掉。為什麼這些元素可以直接丟掉？

| # | 選項 | 描述 |
| - | ---- | ---- |
| **A** | **它們比 nums[i] 早出窗，值又不大於 nums[i]** ✅ | 以索引與數值兩個層面同時考慮這些元素的處境 |
| B | deque 必須保持有序才能對它二分搜尋 | 查詢最大值時需要在 deque 上做 O(log k) 查找 |
| C | 它們的索引已經超出當前窗口左界 | 索引小於 i - k + 1 的元素不再屬於當前窗口 |
| D | deque 容量上限是 k，必須先騰出位置 | 窗口大小固定，容器內元素數不能超過 k |

- 使用者答案：**A** — ✅ pass

### Q3 — 03-Stack / 0739 Daily Temperatures — Output prediction

附上的程式碼片段（彈出條件被改成 `<=`）：

```cpp
// temperatures = [30, 30, 41]
vector<int> dailyTemperatures(vector<int>& t) {
  int n = t.size();
  vector<int> ans(n);
  stack<int> waiting;
  for (int i = 0; i < n; ++i) {
    while (!waiting.empty() && t[waiting.top()] <= t[i]) {   // 注意這個比較
      int j = waiting.top(); waiting.pop();
      ans[j] = i - j;
    }
    waiting.push(i);
  }
  return ans;
}
```

> 上面那段 dailyTemperatures（彈出條件寫成 `<=`），輸入 `[30, 30, 41]` 時回傳什麼？

| # | 選項 | 描述 |
| - | ---- | ---- |
| A | `[2, 1, 0]` | 第一天等 2 天、第二天等 1 天 |
| B | `[2, 2, 0]` | 前兩天都等 2 天 |
| C | `[1, 2, 0]` | 第一天等 1 天、第二天等 2 天 |
| **D** | **`[1, 1, 0]`** ✅ | 前兩天都等 1 天 |

- 使用者答案：**看不懂**（無法手動模擬 stack 的 push／pop）— ❌ **lapse**

### Q7 — 06-Linked-List / 0021 Merge Two Sorted Lists — Key insight（結尾寫法）

> 結尾寫 `cur->next = list1 ? list1 : list2;` 而不寫 `if (list1) ... else if (list2) ...`，主要理由是？

| # | 選項 | 描述 |
| - | ---- | ---- |
| A | 三元運算子較快，編譯器能生成 cmov | 差別在執行效率 |
| B | `if／else if` 會漏掉 list2 比 list1 長的情況 | 較長的那串接不上 |
| C | 三元運算子能避免解參考空指標 | 少一次 nullptr 解參考 |
| **D** | **兩串皆空時兩個分支都不成立，`dummy.next` 不會被賦值** ✅ | 回傳值變成依賴 ListNode 的預設建構子 |

- 使用者答案：「有差？不就某一 list 已經結束了 所以另一個 list 接到尾巴就好了」— ❌ **lapse**
- 判定理由：對**非空輸入**的推理完全正確，但漏掉 `list1 == list2 == nullptr` 這個邊界。已用刻意不初始化 `next` 的 struct 編譯示範（本機恰好印出 `nil`，但屬 UB，不保證）。
